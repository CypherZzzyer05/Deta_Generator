## 对生成器的改进依据

新任务可把固定计划划分成更多小分片，并把“同时运行几个样本”独立设置为 4 或 10。空闲槽立即接下一片，以减少最后只剩一个大分片的阶段；已有任务保留原分片编号和归属以便续算。仅修改控制器和命令入口，不需要更改材料、网格或原生求解实现。

控制台应分别显示请求的并发数、存活子生成器数、正在处理的样本及各路最新进度。原生引擎数量和 CPU 活动属于另一种观察证据，应清楚标明，不能把样本 `running` 数量直接写成“引擎同时求解数”。

Windows 四路/十路集成测试使用明确标记的测试替身，在每次 `sample.run` 中设置屏障，检验真实独立 Python 进程是否能同时进入 4 或 10 个测试调用。测试替身不会创建原生 FDTD 引擎，其引擎数应为 0；这些测试只验证启动和调度行为，不验证目标服务器原生十路性能、许可容量或物理准确性。本次审计未进行十路原生服务器试跑。
